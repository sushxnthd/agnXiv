# AgnXiv Research Phase v0 — Frozen Results

**Status:** complete  
**Freeze commit before this report:** `f527fa3162abb5b0bd876dcfe25252f1a30b300a`  
**Date:** 2026-10-18

This closes the first AgnXiv research sprint. It does **not** claim that the full 100-paper research program is complete. The purpose of v0 was to turn the product hypotheses into reproducible experiments, expose the first real bottlenecks, and establish safety-oriented benchmark gates.

The SciCoQA cases are explicitly **diagnostic_nonblind** because their discrepancies are public. They cannot support a clean headline comparison against an unseen benchmark.

## Real-paper diagnostics

Across eight pinned SciCoQA paper/repository pairs:

- mean automation score: **77.8%**
- median: **77.8%**
- range: **55.6–88.9%**
- paper ingest: **8/8**
- quantitative claim compilation: **8/8**
- repository mapping: **8/8**
- environment inference: **8/8**
- command discovery: **7/8**
- artifact resolution: **8/8**
- verification-spec draft: **7/8**
- workflow ordering: **2/8**
- proven explicit observation locator in auto-plan: **0/8**

The important environment result is the distinction between *detecting* an environment and *recovering a reproduction-ready one*. Environment inference succeeded on all eight cases, but only **2/8 (25%)** were judged reproduction-ready. Three cases depended on import-only inference with unresolved historical package versions.

## Centrality

The initial diagnostics exposed a concrete failure: table fragments and reference/baseline numbers could outrank a paper's primary contribution. Sentence-bounded extraction and centrality heuristics improved Koopa and MaskGIT qualitatively.

On the three currently annotated cases:

- Recall@1: **1/3**
- Recall@3: **2/3**
- Recall@5: **3/3**

This is not enough data for a generalization claim. It does establish that top-1 scientific centrality remains a real bottleneck.

## Paper→code localization

Using eight known SciCoQA discrepancy target paths while hiding those labels from the detector:

- Recall@5: **50%**
- Recall@10: **87.5%**
- Recall@25: **87.5%**

This is evidence that repository localization is useful, but it is not yet a discrepancy detector. One case outside the top 25 remains a significant miss.

## Leakage-free output localization

The reported numeric answer is removed from the locator's Claim object before selection.

On 30 curated output cases:

- overall: **30/30**
- selection cases: **26/26**
- abstention cases: **4/4**
- false selections: **0**
- missed selections: **0**

The cases cover reference-vs-observed values, target echoes, split ambiguity, repeated seeds, mean aggregation, multiple metrics on one line, confidence intervals, percentile latency, BLEU, p-values, and common metric aliases.

**Key result:** this component works far better in isolation than in the real auto-planning pipeline. The real diagnostic planner still produced **0/8 proven explicit locators**. The highest-value next research task is therefore integration, not another synthetic locator heuristic.

## RedBench

RedBench v0 now contains 12 adversarial recorded-output cases designed to induce answer matching or unsafe overconfidence.

Observed:

- expected behavior: **12/12**
- false passes: **0**
- false contradictions: **0**
- abstentions: **5**
- decision coverage: **58.3%**

This is a regression result only. Twelve cases cannot establish a production false-pass probability.

## External anchors

### DeepWalk

The famous-paper zero-manifest test remains an important safety demonstration:

- 8/9 planning stages completed
- the system refused unattended certification
- blocker: no proven explicit observation locator
- historical dependency sensitivity remained visible rather than being silently repaired into a possibly different experiment

### Perturbation-Based-Measurements

The external benchmark demonstrates claim-level rather than paper-level semantics:

- the authors' blanket checker cannot currently be certified in the reconstructed floating environment
- a narrower central Pool A claim is independently recomputed from raw released results
- that independent claim is **VERIFIED**
- the adapter does not import the authors' evaluation implementation

This is the current strongest V4-style independent-reimplementation pilot inside the project, but it is still one claim.

## What v0 falsified

Several optimistic assumptions did **not** survive contact with real repositories:

1. **Environment inference is not environment reproduction.**
2. **Finding commands is not enough; choosing and ordering the correct scientific workflow is much harder.**
3. **A good standalone output selector does not automatically yield a safe real-paper locator.**
4. **Claim extraction quantity is not scientific centrality.**
5. **Paper/code lexical localization is useful but insufficient for discrepancy classification.**
6. **High automation percentage is meaningless unless the remaining stage is safety-critical.** DeepWalk's missing 1/9 stage is exactly the stage that prevents answer-guided certification.

## Ranked next research frontier

1. **Real-paper leakage-free locator synthesis.** Freeze the output locator before revealing the reported number and integrate it into auto-plan.
2. **Workflow DAG reconstruction.** Identify the target evaluation command and only the prerequisite commands needed to produce its inputs.
3. **Historical environment archaeology.** Move from import detection to publication-era version recovery.
4. **Centrality-100.** Expand human annotation before tuning further heuristics.
5. **Evidence localization.** Raise target-path recall@5 without exposing discrepancy labels.
6. **Held-out benchmark.** Curate new or properly held-out cases before claiming a false-pass rate or SciCoQA improvement.
7. **Independent evidence and lineage.** Expand beyond the single independent adapter and explicitly model shared-code/checkpoint dependence.

## Publication readiness

The research is **not yet publication-ready as a benchmark paper**. The strongest publishable direction is still:

**Trustworthy Automated Scientific Verification: selective correctness, abstention, leakage-free observation selection, and execution-grounded evidence.**

To make that defensible, the minimum next dataset is a held-out multi-paper set large enough to estimate false-pass risk with confidence intervals. AgnXiv should not claim a ≤1% false-pass rate until the sample size makes that statement statistically meaningful.
